# YOLO Detect (Android)

Распознавание объектов в реальном времени (камера) и на фото. Работает офлайн через ONNX Runtime.
Есть выбор движка (быстрый / классический), гибкая настройка разрешения и **свои модели**, которые
сохраняются в списке, и у каждой — собственные настройки.

## Как собрать APK
1. Создай репозиторий на GitHub и загрузи **всё содержимое архива** (папка `.github` тоже!).
2. Вкладка **Actions** → **Build APK** (запускается сам после push или через Run workflow).
3. Через ~10–15 минут в завершённом запуске внизу **Artifacts** → `YoloDetect-apk` → скачай, распакуй, установи `app-debug.apk`.

`models/yolo26n.pt` автоматически конвертируется в ONNX на 5 размеров (256/320/416/480/640) и вшивается в APK
как встроенная модель.

## Модели
Кнопка **Модели** — список моделей:
- нажатие на модель — сделать активной;
- **⚙** — настройки именно этой модели;
- **✕** — удалить (встроенную удалить нельзя);
- **＋ Добавить модель (.onnx)** — выбрать файл с телефона. Он копируется в память приложения и остаётся в списке.

Что настраивается у каждой модели: название, движок, где считать, потоки, разрешение входа, прямоугольный вход,
пороги (уверенность, NMS IoU), максимум объектов, свои названия классов. Фильтр классов тоже хранится по моделям.

Поддерживаемые форматы выхода: end-to-end `[N,6]` (YOLO26, YOLOv10), `[4+nc, N]` и `[N, 4+nc]` (YOLOv8/11),
YOLOv5 с objectness (если в модели есть имена классов).

### Как получить .onnx из .pt
- **Через GitHub:** положи `.pt` в `models/`, затем Actions → **Convert model** → Run workflow (укажи путь и размер,
  галочка *dynamic* позволит менять разрешение в приложении). Скачай артефакт `ONNX-Model`.
- **Локально:** `pip install ultralytics` и `yolo export model=my.pt format=onnx imgsz=640 dynamic=True`.

Если ONNX экспортирован с динамическим размером, в настройках модели доступно любое разрешение (кратное 32)
и прямоугольный вход. Если размер фиксированный, используется он.

## Движки
- **Быстрый (новый)** — подготовка кадра по заранее посчитанным таблицам, массовое копирование в буфер,
  чтение результата без вложенных массивов, быстрая постобработка, расширенная оптимизация графа ORT.
  Поддерживает XNNPACK (ускоренный CPU на ARM).
- **Классический (старый)** — прежняя реализация, на случай если на устройстве что-то работает нестабильно.

Где считать: **CPU**, **XNNPACK** (только быстрый движок), **NNAPI** (GPU/NPU/APU, режим FP16).
Если вариант недоступен, приложение само уходит на CPU — в верхней плашке видно, что реально используется.

## Скорость (FPS)
В верхней плашке: FPS и время этапов (подготовка / инференс / постобработка).
Что даёт максимум FPS: размер входа 256–320, быстрый движок + XNNPACK (или NNAPI), разрешение камеры 320×240,
качество превью «Низкое», частота камеры «До 60/120» (если камера поддерживает).

## Общие настройки (кнопка «Настройки»)
Разрешение анализа камеры (320×240 … 1920×1080, 4:3 и 16:9), качество превью, целевая частота кадров камеры.
